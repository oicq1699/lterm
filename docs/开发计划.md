# lterm — 现代 SSH 客户端开发计划

> Rust + Tauri 实现的跨平台 SSH 终端客户端，目标平台：Windows x64 / Linux x64 (mint)。

---

## 1. 目标与范围

### 核心功能（MVP）
| 功能 | 说明 |
|---|---|
| SSH 连接 | 支持 用户名+密码、私钥文件、ssh-agent 三种认证方式 |
| 服务器管理 | 以文件形式持久化到程序数据目录，启动时一次性读入内存 |
| 模糊查询 | 按标题/备注/用户名/主机等多关键字（空格分隔）模糊搜索 |
| 终端仿真 | 彩色输出、true color、支持 TUI（zsh、zellij、vim 等）正确渲染 |
| 剪贴板 | 复制/粘贴，行为对齐 PuTTY（选中即复制可配置、Ctrl+Shift+V 粘贴、右键粘贴） |
| SFTP | 文件浏览、上传、下载（类 WinSCP 双栏界面，可后置到 Phase 3） |

### 非目标（暂不做）
- 保存密码（明确依赖 ssh-agent / key）
- 多路会话标签页管理可先做简单版，后期增强
- macOS 支持、ARM 架构
- 端口转发 / 跳板机 / 代理链（预留结构，Phase 4 可选）

## 2. 技术选型

### 2.1 总体架构

```
┌─────────────────────────────────────────────┐
│  Tauri WebView (前端)                        │
│  xterm.js + 自定义 UI (服务器列表/SFTP面板)   │
└──────────────┬──────────────────────────────┘
               │ invoke / event (IPC)
┌──────────────┴──────────────────────────────┐
│  Tauri Rust 核心                              │
│  ├─ session   : russh 客户端 + PTY 通道       │
│  ├─ sftp      : russh-sftp 协议通道           │
│  ├─ store     : 服务器档案 JSON 读写           │
│  ├─ fuzzy     : fuzzy-matcher 多关键字搜索     │
│  └─ agent     : ssh-agent (页面文件/unix socket)│
└──────────────┬──────────────────────────────┘
               │ tokio 异步任务
        SSH Server (TCP 22)
```

### 2.2 关键依赖

| 用途 | Crate / 库 | 理由 |
|---|---|---|
| 应用框架 | `tauri` v2 | 跨平台、体积小、Rust 后端 |
| SSH 协议 | `russh` | 纯 Rust、活跃维护、支持密码/密钥/agent、PTY、channel |
| SFTP | `russh-sftp` | 与 russh 同生态，基于 channel 的 SFTP v3 客户端 |
| 密钥解析 | `russh-keys`（或 `ssh-key` crate） | 解析 openssh 私钥、对接 agent |
| ssh-agent | `ussh-ssh-agent-client` / russh 内置 agent 支持 | Windows page agent + Unix `$SSH_AUTH_SOCK` |
| 异步运行时 | `tokio` | russh 依赖 |
| 模糊匹配 | `fuzzy-matcher`（SkimMatcherV2） | 与 fzf 同款算法，多关键字空格切分自行实现 AND 逻辑 |
| 序列化 | `serde` + `serde_json` | 档案存储 |
| 数据目录 | `tauri-plugin-store` 或直接用 `app_config_dir` | 优先裸文件 JSON，符合"文件方式保存"需求 |
| 前端终端 | `xterm.js`（`@xterm/xterm` + fit/web-links addon） | 业界标准 VT100+ 仿真，true color、TUI 兼容性好 |
| 剪贴板 | `tauri-plugin-clipboard-manager` | 系统剪贴板读写 |
| 前端框架 | `Svelte` 或 `React`（建议 Svelte，轻量） | UI 面板：列表、SFTP 双栏、设置 |

> **前端终端是渲染正确性的关键**：xterm.js 被 VS Code、Hyper 等验证，对 zellij/vim/htop 等 TUI 的兼容是目前 Web 终端方案中最好的。自研 VT 解析器成本极高，不建议。

### 2.3 数据流设计（终端）

- 键盘输入：xterm.js `onData` → `invoke("write", {id, bytes})`（bytes 用 base64 或 Uint8Array）
- 远端输出：russh PTY channel 收到数据 → Tauri `emit("pty-data", {id, bytes})` → xterm.js `term.write()`
- **性能要点**：
  - 输出高频时不能每包都走 IPC 事件；在 Rust 侧做 **合帧缓冲**（如 4–16ms 窗口聚合）再推送
  - resize 通过 `channel.window_change(cols, rows, ...)` 传递，前端用 fit addon 监听容器尺寸变化并 debounce

## 3. 模块设计

### 3.1 服务器档案管理（`store`）

存储位置：`{app_config_dir}/lterm/servers.json`（Windows: `%APPDATA%\lterm`，Linux: `~/.config/lterm`）

```jsonc
{
  "version": 1,
  "servers": [
    {
      "id": "uuid-v4",
      "name": "mint-工作站",          // 标题
      "host": "192.168.1.10",
      "port": 22,
      "username": "root",            // 必留
      "auth": {
        "method": "agent",           // password | key | agent
        "key_path": null,            // method=key 时有效
        "key_passphrase_saved": false// 密码永远不落盘
      },
      "remark": "家里的主力机",        // 备注，必留
      "group": "home",               // 可选分组
      "color": "#4A9EFF",            // 可选标签色
      "created_at": "...", "updated_at": "..."
    }
  ]
}
```

- 启动时一次性读入内存（`Vec<ServerProfile>` + `HashMap<id, _>`），之后所有查询走内存
- 写入策略：全量序列化 + 写临时文件 + `rename` 原子替换，防断电损坏
- 并发写：进程内 `Mutex`，多开实例先不做文件锁（文档注明）

### 3.2 模糊查询（`fuzzy`）

- 输入按空格切分为 N 个关键字
- 每个关键字对可搜索字段（name / remark / username / host）做 `SkimMatcherV2.fuzzy_match`，取字段最大值
- 所有关键字必须命中（AND），总分 = 各关键字分数之和；分数相同按最近使用时间排序
- 结果高亮片段返回前端（fuzzy-matcher 能给出 match 位置）

### 3.3 SSH 会话（`session`）

- 每个连接一个 `SessionHandle { id, JoinHandle, ... }`，支持多标签并发
- 认证流程：
  1. `agent`：枚举 agent 中所有密钥逐一尝试（`ussh-ssh-agent-client`）
  2. `key`：读私钥文件 → 若有 passphrase 弹窗询问（不落盘）
  3. `password`：连接后弹窗询问密码（可勾选"本次会话记住"）
- 处理 `Authenticate` 各分支回调、`Unsupported` 算法告警、断线检测（channel close / TCP error）
- 重连：提供手动"重新连接"按钮（自动重连 + 会话恢复放 Phase 4）

### 3.4 SFTP（`sftp`）

- 在同一 russh session 上开 `subsystem("sftp")` channel，用 `russh-sftp` client
- 命令面：`list(path)` / `mkdir` / `remove(file|dir 递归)` / `rename` / `upload(local, remote)` / `download(remote, local)` / `stat`
- 上传下载：分块（32KB）读写，进度经事件推送（debounce ≤ 10Hz）
- 权限位 / 属主显示：SFTP `ATTR` + `STAT_TO_OWNER` 扩展（agent 扩展支持时显示，否则简化为 size+mtime）
- UI：双栏（本地 | 远端），拖拽上传、双击下载、工具栏按钮兜底

### 3.5 剪贴板与交互（前端）

- 复制：选中即复制（可开关，默认开，PuTTY 风格）+ `Ctrl+Shift+C`
- 粘贴：`Ctrl+Shift+V` + 鼠标中键 / 右键（可配置）
- 换行粘贴确认：粘贴含 `\n` 时弹出确认（防粘贴攻击），可关闭
- 终端字体：默认 `JetBrains Mono` / `Sarasa Mono SC`（中文宽字符 CJK 宽度是 TUI 对齐的关键，xterm.js 需开启 `windowsMode` 或选对字体）

## 5. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| xterm.js 对某些 TUI 渲染瑕疵（zellij 边框错位等） | 中 | 早期就引入 zellij 实测；字体 + windowsMode 调优；必要时升级到 xterm 5.x 最新 |
| IPC 高频输出瓶颈（cat 大文件、`yes`） | 中 | Rust 侧合帧 + 批量事件；实测吞吐（目标 ≥ 5MB/s 渲染不卡） |
| russh-sftp 某些服务器扩展不支持 | 低 | 降级显示（不显示权限/属主）；错误透传 UI |
| Windows ssh-agent（页面板）与 OpenSSH agent 行为差异 | 中 | 两种实现都测；文档引导用户启用 `ssh-agent` 服务 |
| 中文输入法在 WebView 内组合输入 | 低 | xterm.js `onData` 已处理 composition；两平台实测 |
| Tauri v2 插件 API 变动 | 低 | 锁定小版本号 |
